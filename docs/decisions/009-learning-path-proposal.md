# ADR-009 · ID를 보존하는 별도 마스터 학습 경로 제안

- 상태: 제안안 구현 완료 · 교육과정/사용자 검토 대기
- 작성일: 2026-11-01
- 관련: [ADR-007](007-level-allocation.md), [170단원 배치 검토](../reviews/NEXT_STEP/curriculum-path-proposal.md), [구현 감사](../reviews/NEXT_STEP/implementation-audit.md)

## 맥락

기존 170단원 제안 v0.1.0은 요청된 최신 LEVEL 수량·주제와 다르다. 운영 `Unit`의 `level/order`와 M[0-8]-NN ID를 재사용하고 있어, 그 값을 새 경로 분류에 덮어쓰면 기존 순번과 제안 분류를 동시에 표현할 수 없다. 기존 학습 기록의 key는 unitId이므로 ID와 기록은 그대로 보존해야 한다.

새 요청의 기준 수량은 12/14/18/22/24/20/22/18/20이다. 공식 자료는 2028 수능 과목을 대수·미적분Ⅰ·확률과 통계로 안내하지만 Math 90의 170개 분할이나 LEVEL 수량을 정하지 않는다. 교육부 고시 별책 8의 공식 원문 다운로드는 조사 환경에서 403으로 막혔으며 후보 성취기준 코드를 운영 단원에 연결하지 않았다.

## 결정

1. 기존 `Unit.level/order`, ID, 제목, 개념, 제안 본문과 기존 M0 기록을 변경하지 않는다.
2. 별도 `learningPath` proposal 모델에서 각 기존 unitId를 `pathLevel/pathOrder`에 매핑한다. 이 데이터는 제안 curriculum·콘텐츠·정답·운영 registry와 분리한다.
3. 계획 화면과 JSON 내보내기는 요청 기준 및 현재 경로 후보를 함께 보여준다. 경로 필터와 카드 표시는 `learningPath`를 사용하고 원래 분류도 역사 정보로 보존한다.
4. 첫 검토 후보는 LEVEL 7의 모평균·모비율 추정 첫 학습을 유지하기 위해 경로 수량을 12/14/18/22/24/20/22/20/18로 제시한다. LEVEL 1/2 제목도 현 후보의 실제 범위에 맞춰 넓힌다. 요청 수량·제목을 바꾸는 것은 사용자 승인 전까지 **제안 상태**로 유지한다.
5. LEVEL 8 배치 항목은 전이 후보·점검·전략 연습·독립 평가·범위 미확인 확장으로 구분한다. 이 분류는 실제 lesson을 만들거나 수능 출제 가능성을 보장하지 않는다.
6. `canonicalManifest`는 비어 있고 앱 학습 라우트는 기존 12개만 등록한다. DB 마이그레이션·진도 재배치·계정 변경은 없다.

## 검증

- 모든 기존 단원 ID가 정확히 한 번만 매핑되어야 한다.
- pathOrder는 중복 없이 1~170 연속이며 LEVEL별 제안 수량을 만족해야 한다.
- 기록된 선수 단원이 해당 단원의 경로 앞에 있어야 한다.
- 기존 Unit/등록 manifest/기본 제안 버전과 빈 canonical manifest를 보존해야 한다.
- 계획 화면 검색·필터·JSON 다운로드에서 후보 경로를 확인하며 미등록 단원은 계속 404여야 한다.
- 교육적 경계, 제안 제목, 7/8 수량은 사용자·전문가 검토가 남아 있다. 이 안만으로 정본 출시 게이트가 통과할 수 없다.

## 결과

별도 경로 계약과 검증기를 추가하고 로그인 후 읽기 전용 계획 화면에 요청/후보 비교를 노출한다. 문항·콘텐츠 구현은 기존 12개를 넘지 않는다. 다음으로 경로 수량/제목 검토를 마치면 M1-01~M1-05 콘텐츠 묶음을 별도 제안으로 시작한다.
