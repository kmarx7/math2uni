# ADR-009 · ID를 보존하는 별도 마스터 학습 경로

- 상태: **Math 90 개발 경로 배분 확정 · 공식 canonical/운영 경로 아님**
- 작성일: 2026-11-01
- 갱신일: 2026-11-03
- 관련: [ADR-007](007-level-allocation.md), [마스터 학습 경로 결정안](../reviews/NEXT_STEP/curriculum-path-proposal.md), [구현 감사](../reviews/NEXT_STEP/implementation-audit.md)

## 맥락

기존 170단원 제안 v0.1.0은 요청된 최신 LEVEL 수량·주제와 다르다. 운영 `Unit`의 `level/order`와 M[0-8]-NN ID를 재사용하고 있어, 그 값을 새 경로 분류에 덮어쓰면 기존 순번과 제안 분류를 동시에 표현할 수 없다. 기존 학습 기록의 key는 unitId이므로 ID와 기록은 그대로 보존해야 한다.

새 요청의 기준 수량은 12/14/18/22/24/20/22/18/20이다. 공식 자료는 2028 수능 과목을 대수·미적분Ⅰ·확률과 통계로 안내하지만 Math 90의 170개 분할이나 LEVEL 수량을 정하지 않는다. 교육부 고시 별책 8의 공식 원문 다운로드는 조사 환경에서 403으로 막혔으며 후보 성취기준 코드를 운영 단원에 연결하지 않았다.

## 결정

1. 기존 `Unit.level/order`, ID, 제목, 개념, 제안 본문과 기존 M0 기록을 변경하지 않는다.
2. 별도 `learningPath` proposal 모델에서 각 기존 unitId를 `pathLevel/pathOrder`에 매핑한다. 이 데이터는 제안 curriculum·콘텐츠·정답·운영 registry와 분리한다.
3. 계획 화면과 JSON 내보내기는 요청 기준 및 현재 경로 후보를 함께 보여준다. 경로 필터와 카드 표시는 `learningPath`를 사용하고 원래 분류도 역사 정보로 보존한다.
4. 확정 개발 경로는 사용자 지정 수량 `12/14/18/22/24/20/22/18/20`을 따른다. LEVEL 1/2 표시명은 실제 배치의 수 기초·초기 방정식 및 고교 대수 진입을 반영해 넓힌다.
5. M7-19·M7-20은 LEVEL 7을 18개로 유지하기 위해 LEVEL 8 첫 두 슬롯에서 처음 가르치는 통계 추정 단원으로 둔다. `first-instruction-candidate`로 정직하게 표시하고, LEVEL 7 선수 개념을 확인하며, 이를 전이 연습으로 잘못 분류하지 않는다.
6. 나머지 LEVEL 8 배치 항목은 전이 후보·점검·전략 연습·독립 평가·범위 미확인 확장으로 구분한다. 어느 항목도 수능 출제 가능성을 보장하지 않는다.
7. `canonicalManifest`는 비어 있고 앱 학습 라우트는 운영 승인된 기존 12개만 등록한다. DB 마이그레이션·진도 재배치·계정 변경은 없다.

## 검증

- 모든 기존 단원 ID가 정확히 한 번만 매핑되어야 한다.
- pathOrder는 중복 없이 1~170 연속이며 LEVEL별 제안 수량을 만족해야 한다.
- 기록된 선수 단원이 해당 단원의 경로 앞에 있어야 한다.
- 기존 Unit/등록 manifest/기본 제안 버전과 빈 canonical manifest를 보존해야 한다.
- 계획 화면 검색·필터·JSON 다운로드에서 후보 경로를 확인하며 미등록 단원은 계속 404여야 한다.
- 검증된 공식 성취기준 매핑, 독립적 사람 교육 검토, 정본 등록 및 게시 승인 없이 이 안으로 출시 게이트를 통과시킬 수 없다.

## 결과

별도 경로 계약과 검증기를 추가하고 로그인 후 읽기 전용 계획 화면과 JSON 내보내기를 연결했다. 현재 제안 단원 158개 중 60개가 개발 preview에 연결됐다. 세부 배치와 최신 검토 상태는 [마스터 학습 경로 결정안](../reviews/NEXT_STEP/curriculum-path-proposal.md), [DELIVERY_PLAN.md](../DELIVERY_PLAN.md), [ROADMAP.md](../ROADMAP.md)을 따른다.
