# M0-01 자료조사 및 자체 문항 초안

작성 역할: Research & Content Agent. 확인일: 2026-11-01. 이 보고서는 자료 조사와 편집 초안 결과이며, 공식 교육과정 매핑·전문가 검수·사람의 게시 승인을 뜻하지 않는다.

## 확인한 범위

1. [교육부 2022-33호 교육과정 고시](https://www.moe.go.kr/boardCnts/viewRenew.do?boardID=141&boardSeq=93458&lev=0&statusYN=W)에서 수학과 교육과정이 별책 8임을 확인했다. 이 작업에서는 첨부 원문 전체와 단원별 세부 성취기준을 대조하지 않았으므로 공식 코드와 매핑은 미검증으로 남긴다.
2. [NCETM의 십진 자리값 지도 설명](https://www.ncetm.org.uk/features/multiplying-by-10-is-it-ok-to-just-put-a-zero/)은 끝에 0을 붙이는 요령만 가르치기보다 자리값과 단위 묶음의 변화 이해를 먼저 다룰 것을 설명한다. 이를 참고해 숫자·자리·단위의 텍스트 대응과 묶음 교환 활동을 제안했다. 영국의 교수 자료이며 한국 교육과정 성취기준이나 학생 집단의 오류 빈도 근거로 사용하지 않는다.
3. [Oak National Academy의 자리 유지 지도 자료](https://www.thenational.academy/teachers/programmes/maths-primary-ks2/units/understand-what-happens-when-a-number-is-multiplied-or-divided-by-10-and-100/lessons/explain-the-use-of-placeholders-when-multiplying-whole-numbers-by-100)에서 단순한 0 추가 패턴과 자리값의 변화 의미를 혼동할 수 있다는 설명을 확인했다. 수업 슬라이드·퀴즈·활동지를 가져오지 않았고 프로젝트의 자체 예제만 작성했다.
4. [교육부 2028학년도 예시문항 안내](https://www.moe.go.kr/boardCnts/viewRenew.do?boardID=294&boardSeq=103113&lev=0&m=020402&opType=N&s=moe&statusYN=W)에서 공식 예시문항 안내와 첨부 경로를 확인했다. 평가원·수능 누리집 직접 열람은 도구 결과에 읽을 수 있는 본문이 없어 독립 문항 조사는 미완료다. 이 보고서에는 기출·예시 문항을 복제하지 않았으며 자체 제작 문항을 수능의 실제 난도나 유형 빈도로 주장하지 않는다.

구조화된 자료별 URL·확인 상태·사용 범위·이용 조건은 `sources.json`에 기록했다. 접근 성공과 첨부 원문 검증을 구분한다.

## 초보 학습자에게 확인할 오개념

다음은 문항·피드백 설계를 위한 점검 가설이다. 한국 학생에게 특정 비율로 발생한다는 조사 결과가 아니다.

- 숫자 기호 6과 6이 나타내는 값 600을 같게 보는 경우: 자리 이름·숫자·단위를 분리해 말하게 한다.
- 0인 자리의 기여량이 없으므로 그 자리를 지워도 수가 같다고 생각하는 경우: 4,052와 452를 자리표에 나란히 둔다. 삭제한 0보다 **왼쪽**의 4가 천에서 백으로 이동하고, 오른쪽의 5십·2일은 그대로임을 확인한다.
- 묶음 수가 달라지면 전체 양도 반드시 달라진다고 생각하는 경우: 10십과 1백을 교환하고 양을 비교한다.
- 같은 자리 수끼리 낮은 자리나 숫자의 합만 비교하는 경우: 높은 자리에서 처음 다른 위치를 찾아 그 뒤의 낮은 자리 영향이 결정을 뒤집지 못함을 조작으로 확인한다.
- 한 자리 숫자를 바꾸라는 조건을 수 전체에 그 숫자를 더하라는 뜻으로 읽는 경우: 조작 전후에 바뀐 열만 표시한다.
- 카드로 가장 작은 네 자리 수를 만들 때 0을 맨 앞에 놓는 경우: 처음 자리가 0이면 네 자리 자연수가 아니라는 조건을 먼저 확인한다.

## 문항 초안과 풀이 전략

`src/data/m001-expansion.json`에는 기존 3개 원형 정의(identify/compose/infer)를 그대로 재사용하고 신규 7개 원형을 더한 총 10개 전략의 **새 고정 문항 30개**가 있다. 전략마다 연습 2개와 별도 평가 1개이므로 연습 20개·평가 10개다. 같은 전략의 수치 변형은 새 원형으로 세지 않는다.

| 원형                        | 핵심 사고                                    | 새 문항 수 |
| --------------------------- | -------------------------------------------- | ---------- |
| identify (기존)             | 자리 숫자와 자리 단위를 연결해 값 산출       | 3          |
| compose (기존)              | 자리별 양의 합으로 한 수 구성                | 3          |
| infer (기존)                | 주어진 숫자 사이의 조건을 해결해 수 구성     | 3          |
| m001x-zero-placeholder      | 0 삭제 전후의 표현과 자리 변화 분석          | 3          |
| m001x-representation-match  | 여러 분해 표현 중 원래 수와 동치인 표현 판정 | 3          |
| m001x-regroup-equivalence   | 표준·비표준 묶음 교환의 양 보존              | 3          |
| m001x-compare-lexicographic | 높은 자리의 첫 차이로 순서 관계 결정         | 3          |
| m001x-digit-change          | 한 자리 조작의 양의 증가·감소량 해석         | 3          |
| m001x-error-diagnosis       | 주장의 자리·숫자·값을 각각 검증해 오류 탐지  | 3          |
| m001x-constrained-extrema   | 카드당 1회·선행 0 금지 아래 극값 구성        | 3          |

신규 원형 중 표현 대응은 compose와 소재가 겹치지만, 한 수를 만드는 응답과 여러 표현의 동치 판단이라는 사고 목표를 구분한다. 실제 학습 결과에서 차별성이 없으면 병합할 수 있으며 10개를 유지하려고 원형 수를 고정하지 않는다.

현재 문항은 D1~D3이다. 단순 카드 배치 문항을 D5로 과장하지 않는다. D4~D5는 추가 제약·새 상황으로의 전이 등 별도 설계·검수 이후에 작성하며 기본 단원 완료의 필수 장벽으로 삼지 않는다. 정답은 객관식/정수만 사용하고 임의 수식 실행은 없다.

## 검증 인계

각 문항의 `verification` 항목은 정답 문자열 복사 대신 원래 수·자리 단위·묶음·조건·선택지의 수학적 주장을 저장한다. Developer & QA Agent는 이를 독립 계산으로 검증한다. 본문에 숫자와 조건이 맞는지는 별도 교육 검토가 필요하다.

- 자리값: 숫자열/자리 추출 독립 모델
- 합성·동치 선택: count × unit의 가중합, 정확히 하나인 정답 선택지
- 조건 추론: 조건에서 구한 십의 자리 후 자리별 재구성
- 0 삭제: 명시된 0 기반 인덱스의 한 글자 삭제 결과
- 묶음 교환: 알려진 묶음 이외의 양과 단위 개수, 교환 전후 총량
- 비교: 정수 대소와 자리별 사전식 비교
- 자리 변화: 수정된 수와 원래 수 사이의 절댓값, 묶음 변화량의 독립 비교
- 오류 진단: 주어진 모든 주장 중 정확히 하나의 거짓
- 카드 극값: 4개 카드의 모든 순열에서 선행 0을 제외한 최소/최대

초안의 상태는 **draft**, `reviewHistory`는 빈 배열이다. 작성 과정의 자체 계산을 사람 승인 이력이나 개발자의 독립 검증 이력으로 꾸미지 않았다. 독립 계산을 통과해도 사람 검수가 끝나기 전 production 공개는 차단해야 한다.

## 남은 검수

공식 교육과정 원문/세부 성취기준 대조, 실제 한국 초보 학습자의 이해도, 설명 충분성, 문항 원형의 교육적 차별성, 스크린리더 전달, D4~D5 필요성은 수동·사용자 검토 대상이다. 학습 효과나 수능 90점 달성은 이번 제작만으로 검증되지 않는다.
