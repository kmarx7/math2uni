## 확인한 사용자 흐름

1. 대시보드에서 M0-01 진입 → 자리표 조작 → 오답 제출 → 정답/해설 → 오답노트.
2. 오답을 다시 풀어 교정 → 새로고침 → 오답 해소와 누적 기록 유지.
3. 로컬 프로필 생성/전환 → 기록 분리. 지연 응답 도착 중 프로필 전환도 타인 기록에 섞이지 않음.
4. 평가 GET에는 채점 규칙·정답·해설이 없음. 부분 제출은 400, 연습 API에서 평가 문항 조회는 404.
5. 평가 3문항 전체 제출 → 점수/해설 → 새로고침 후 평가 점수 유지.
6. 독립 연습 3원형 + 평가 + 9블록 확인 → 단원 완료 → 재로드 후 완료 유지.
7. 시간을 하루 뒤로 이동 → 예정 복습 6개 → 한 문제 재풀이 → 남은 복습 5개.
8. 커리큘럼에 12개 초안과 한 개 학습 링크 구분, LEVEL 8 준비 중, 미공개 단원 404.
9. 모바일에서 문서 전체 수평 넘침 없음. 별도 브라우저로 390×844 및 데스크톱 대시보드·학습 화면도 시각 확인.

## 수학·데이터 검증

- 자리값 템플릿은 1,000~9,999 및 4개 자리의 모든 조합을 독립 문자열 자리 분해 모델과 비교한다. 목표 숫자 0 / 범위 밖 / 비정수 / 잘못된 자리를 거부한다.
- 객관식, 부호 있는 정수, 정확한 유한 소수, 동치 분수를 검사한다. 분모 0, NaN, 무한대, 지수, 임의 코드, 초과 길이와 입력 형식을 거부한다. 수식은 unsupported이다.
- 문항 ID/정규화 본문 중복, 정답 자기 채점, 풀이의 정답 값 포함, 출처·버전·사람 승인 게이트를 검사한다.
- 고정 등록 manifest를 사용해 마지막 단원 삭제도 검사하고, 개념 누락·중복 ID·학습 순서·선수 그래프 순환과 모듈 의존 순환을 검사한다.
- production에서 개발 preview 플래그를 켜도 미승인 AI 문항은 GET/POST 모두 차단된다. 현재 승인 파일은 빈 배열이다.
- 힌트/즉시 재시도 감점, 동일 문항·버전 증거 중복 제거, 숙달 완료 조건, 복습 1/3/7일 및 실패 재설정, 저장소 손상/프로필 불일치를 검사한다.

## 수정한 문제와 한계

초기 검증에서 블록 본문에 ID용 길이 제한이 적용된 오류와, 포매터의 따옴표 변경을 오탐한 소스 경계 검사를 수정했다. 개발 서버의 origin 허용 목록을 추가했고 모바일 내비게이션의 가로 스크롤을 제거했다. 자동 검사를 사람 승인으로 기록하지 않도록 초기 검수 메타데이터와 운영 공개 게이트를 수정했다.

네트워크 DNS 제약으로 의존성을 npm 캐시에서 설치했고 Playwright 1.61.1은 로컬의 같은 버전 설치본을 복사하여 사용했다. 공식 레지스트리 URL/무결성 정보가 있는 package-lock을 유지하며 lock dry-run을 통과했다. 새 환경의 `npm ci` 전체 실행은 아직 검증하지 않았다.

이 결과는 한 단원 MVP의 동작 검사다. 독립 교육 전문가 검수, 실물 모바일 기기, 스크린리더 사용자 평가, PostgreSQL/RLS, 인증, 고부담 시험 보안, 실제 성적 향상은 검증하지 않았다. 170단원 플랫폼 전체 완료나 운영 콘텐츠 출시 가능 상태로 보고하지 않는다.

테스트 fixture는 실제 Supabase 응답 모양의 HTTP 서비스이며 실제 DB나 이메일을 사용하지 않는다. 테스트용 비밀번호/계정/JWT 키는 더미 값이고 운영 인증 우회 코드는 없다. 위 결과를 실제 사용자 계정의 클라우드 로그인·이메일 인증·RLS 보안 검증 통과로 해석하면 안 된다. 기존 170단원 canonical 게이트 미통과 상태도 유지한다.

# 실제 Supabase 연결 검증

사용자가 전용 프로젝트 연결에 동의한 후 `kmarx7's Org`에 Math 90 프로젝트를 생성했다. 생성 직전 다시 조회한 비용은 월 $0, 리전은 서울(ap-northeast-2), project ref는 `aaeitniisrtssiuertxo`이다.

- 프로젝트 상태 ACTIVE_HEALTHY, 빈 public 스키마 확인 후 `account_learning_progress` 마이그레이션 적용 성공.
- 원격의 실제 migration 버전 `20261031083910`에 맞춰 로컬 파일명을 동기화했다. 중복 적용하지 않는다.
- `.env.local`에 실제 프로젝트 URL과 publishable 키를 설정했다. `git check-ignore .env.local`로 Git 제외를 확인했다. service_role/secret 키나 사용자 비밀번호는 앱에 설정하지 않았다.
- 실제 Auth `/auth/v1/settings`에서 이메일 가입 활성화, 가입 허용, 이메일 자동 확인 비활성화(이메일 인증 필요), 익명 가입 비활성화를 확인했다.
- 실제 DB에서 authenticated 역할과 `auth.uid()`를 사용하여 본인 기록 SELECT/INSERT/UPDATE 성공, 다른 계정의 SELECT 비노출/INSERT 거부/UPDATE 0행 및 user_id 소유권 재지정 거부를 검사했다. 전체 트랜잭션을 롤백했다. 재현 SQL은 `supabase/tests/learning_progress_rls.sql`이다.
- 롤백 후 실제 auth.users와 learning_progress가 모두 0행임을 확인했다. anon SELECT 권한 없음, RLS 활성화 및 FORCE 설정을 확인했다.
- Supabase security/performance advisors: 둘 다 지적 사항 0개.
- 실제 앱 `/login`, `/signup` HTTP 200, 비로그인 `/api/progress`와 `/api/practice` HTTP 401. 존재하지 않는 더미 계정의 로그인은 401로 거부했고 실제 Auth 로그에서도 400 요청 완료를 확인했다. 이 검사는 가입 메일을 보내거나 실제 사용자 계정을 생성하지 않는다.
- 실제 연결 설정을 적용한 상태에서 lint, 타입 검사, 단위 테스트 71개, 프로덕션 빌드가 통과했다. 보호 학습 경로는 쿠키 기반 동적 경로로 빌드됐다.
- 연결 후 모의 HTTP fixture E2E 전체 재실행은 데스크톱 8개가 통과한 뒤 실행기/teardown의 240초 시간 제한에 도달해 모바일 8개가 실행되지 않았다. 이 재실행을 전체 통과로 기록하지 않는다. 앞선 계정 기능 구현 단계에서 16개가 모두 통과한 결과와 구분한다. 이어 모바일만 별도 실행하여 8개 테스트의 통과를 확인했으나 이 실행도 종료 플러그인의 240초 시간 제한으로 exit 1이 되었다. 두 실행에서 각각 8개 검사 자체는 통과했지만 실행기 종료 실패 때문에 전체 QA 통과로 처리하지 않는다.

**남은 사용자 확인:** 실제 이메일로 회원가입하여 인증 메일을 수신하고 인증 링크를 완료한 뒤 로그인하는 과정은 자동으로 수행하지 않았다. 개인 비밀번호는 요청하거나 대신 설정하지 않았다. 연결 도구에 Auth 설정 변경 기능이 없고 CLI/관리 화면은 별도 로그인이 필요해 Site URL/Redirect URL 및 SMTP를 임의로 변경하지 않았다. 로컬 기본 주소는 `http://localhost:3000`이며, 실제 이메일 발송/다른 배포 도메인 설정은 가입 시 또는 배포 시 확인해야 한다.

모의 HTTP fixture를 사용하는 E2E 결과와 위 실제 DB/RLS 검증은 서로 다른 검사다. 위 계정 기능 확장 단계의 “실제 연결 대기” 상태는 이번 연결 작업으로 해소됐다. 실제 사용자 이메일 가입 검증과 전체 170단원 canonical 게이트는 여전히 완료로 표시하지 않는다.

CLI 0.166.0, multi_agent stable/true를 확인했다. 세 standalone TOML과 공통 설정은 docs/agents 템플릿에서 프로젝트 `.codex/`로 복사되었고 설치본이 템플릿과 일치한다. 자동화 실행기의 `codex --strict-config ... exec`는 in-process app-server 초기화 `Operation not permitted`로 막혔다. 이후 사용자가 새 로컬 Codex 세션에서 custom role 세 개를 각각 실행해 발견·완료를 확인했고, 세 역할 모두 파일 변경 없이 설정된 범위를 보고했다고 확인했다. 이 수동 세션 검증은 사용자가 보고한 결과로 기록한다. `--strict-config ... features list`는 CLI에서 지원되지 않는다. 앞선 협업 도구 실행과 프로젝트 TOML 자동 로딩 확인을 구분한다.
