## 교수 명세와 상태

M4-12 예제는 `n=4k=2(2k)`를 근거로 모든 4의 배수가 짝수임을 보인다. M4-13 u5는 홀수인 정수의 제곱이 홀수임을 명시한 뒤 `n²=2`일 때 홀수 가능성을 배제하고 짝수 표현에서 모순을 이끌어낸다. M0-05 홀짝 지식은 선택 진단 전용이며 미등록 선수 단원·자동 진입 차단으로 사용하지 않는다고 적혀 있다.

두 단원의 lesson spec과 blueprint는 `draft`, `publicationApproved:false`, `officialStandards:[]` 상태다. 각 blueprint는 고유 원형 3개, 연습 draft 6개, 평가 문항 0개, 인간 승인 문항 0개를 기록한다. 모든 문항은 `humanVerified:false`이고 사람 검수/게시 승인은 미완료다. 이 독립 재검수는 구현 준비·교육 승인·게시 승인을 뜻하지 않는다.

## Renderer 초안 독립 확인

Research가 명세 수정 사항을 반영한 최신 renderer 초안을 확인했다. M4-12 worked example은 임의의 정수 n을 `n=4k`로 두고 `n=2(2k)`로 바꾸므로 4의 배수이면 짝수임을 일반적으로 증명한다. `n=2`는 역의 반례로만 쓰여 논리 역할이 구분된다.

M4-13 worked example은 원명제의 대우인 “n이 짝수이면 n²이 짝수”를 `n=2k`, `n²=2(2k²)`로 보이고 정수성으로 마무리한다. u5 귀류 설명은 정수의 홀짝 분기를 사용한다. n이 홀수라면 제곱이 홀수여서 `n²=2`와 모순이고, 짝수라면 `n=2k`에서 `1=2k²`가 되어 홀수와 짝수가 같아지는 모순이다. 활동과 확인 질문에도 이 논리 단계가 나타난다.

두 renderer 초안 모두 15개의 고유 학습 단계를 가지며 모든 단계의 block 참조가 존재한다. 각각 6개 소단원 ID가 해당 명세와 일치한다. 8개 공통 블록을 사용하며 `AssessmentBlock`은 없고, `PracticeBlock`은 연습용으로만 표시된다. 인터랙션은 현재 content schema의 `condition-map`으로 임시 표현한다고 명시하며 완성 구현으로 주장하지 않는다. 두 lesson draft와 spec은 계속 draft이며 게시 승인은 false다. 이 확인은 렌더링 동작, 웹 QA, 사람 승인까지 의미하지 않는다.
