# M0-01 Developer & QA 구현 기록

## 기준과 책임

기존 M0-01의 문항 ID, 세 개념(place/compose/infer), 9블록의 확인 기록과 기본 평가 3문항을 보존한다. Curriculum Architect의 설계 인계 후 별도 `extended` 문항 묶음으로 확장한다. 새로운 교육 명세는 AI 설계 검토이며 사람의 콘텐츠 게시 승인을 대체하지 않는다.

## 기존 구조 검사

- 공통 `ProblemSession`은 공개 DTO를 GET하고 서버 채점 결과를 받은 뒤 계정 기록을 교체한다.
- `question-bank/server.ts`만 비공개 정답/해설을 앱 API에 제공한다.
- `scoreAssessment`는 조회된 평가 문항의 정확한 전체 집합을 요구한다.
- 기존 M0-01 평가 문항은 3개이다. 새 평가 초안을 기본 묶음에 합치면 기존 응답·완료 조건과 테스트가 달라지므로 분리한다.
- `NODE_ENV=production`은 개발 preview 플래그를 무시한다. 확장 초안도 동일한 사람 승인 게이트를 통과해야 운영 공개된다.

## 인계 계약

- Research 산출물: `src/data/m001-expansion.json`의 `{families, problems, verification}`.
- 현재 ProblemInstance 계약을 따른 30개 신규 초안, 10개 원형(기존 3개와 신규 7개), 연습 20개/평가 10개.
- verification은 문항 정답을 그대로 반복하지 않는 계산 입력·연산 종류이다. Developer의 별도 계산 모델과 교차 비교한다.
- Bank 함수는 `collection: core | extended`를 받으며 기본값은 core이다.
- 공개 원형 메타데이터는 ID·제목·전략만 포함한다. 공개 문항 DTO는 기존 allowlist를 유지한다.
- 확장 평가 점수는 화면에 표시하되 기존 핵심 평가 점수를 덮어쓰지 않는다. 각 제출·오답·재시도는 문항 ID와 버전으로 저장한다.

## 진행 상태

초기 검사 완료. 교육 설계/문항 인계와 실제 구현·검사 결과는 작업 완료 시 아래에 추가한다. 이 문서는 구현 완료나 게시 승인을 선언하지 않는다.

## 실제 구현 결과

- Curriculum의 `designReview.decision = implementation-ready`(AI 역할의 독립 설계 검토, 사람 게시 승인 아님)를 확인한 뒤 확장 bank를 연결했다.
- `src/data/m001-expansion.ts`는 server-only이며 Research JSON을 Zod로 검증한다. 10개 원형·신규 30문항(연습 20/평가 10)과 각 문항의 독립 검증 입력을 읽는다. 문항 상태는 계속 draft이고 승인 이력을 만들지 않는다.
- 유계 정수·자리 추출·단위 합·조건 구성·0 삭제·비표준 묶음·비교·자리 변화량·잘못된 주장·카드 극값의 10종 검증을 구현했다. 코드/수식을 실행하지 않는다. 실패한 확장 묶음은 preview에서도 제공하지 않는다.
- 객관식의 보기 ID/본문과 계산 입력의 일치도 확인한다. 분해식 보기의 안전한 숫자 합과 오류 설명의 유한 텍스트 형식을 검증하므로, 정답 메타데이터만 맞고 실제 보기를 바꾼 경우도 거부한다.
- `question-bank/server.ts`는 `core | extended` 선택을 받고 기본값은 core이다. 기존 6개 고정 문항과 생성 샘플, 다른 단원 문제는 core에 그대로 남는다. publicFamilies는 현재 제공되는 문항의 원형 메타데이터만 반환하고 공개 DTO에 정답/해설을 추가하지 않는다.
- Orchestrator가 API/공통 UI의 묶음 선택·원형 필터·확장 복습 연결과 확장 평가 점수 격리를 구현했다. 확장 시도는 별도의 collection 태그를 저장하고 기존 핵심 숙달·완료의 증거에 섞지 않는다. 저장 스키마 버전과 과거 collection 없는 기록은 유지한다.
- Developer는 기존 `src/data/problems.ts`를 변경하지 않았다. 기존 ID/버전/평가 3문항은 보존했다.

## 검증 결과와 인계

`npx vitest run tests/m001-expansion.test.ts`: 8개 통과(exit 0). 산술 모델과 별도의 문자열/정확한 정수 덧셈/모든 카드 순열 기준 모델로 30개 정답을 교차 계산했다. 신규 6개 객관식의 중복 정답·보기 일치, 개발/운영 공개 경계, 기본 평가 격리와 잘못 푼 확장 30문항 이후 기존 완료 보존을 검사했다.

`tests/e2e/m001-expansion.spec.ts`에는 데스크톱·모바일 각각 확장 원형 선택→오답→새로고침→오답노트→확장 문항 교정과 분리 평가→기본 점수 보존 검사를 추가했다. 전체 E2E/lint/type/build 실행은 Orchestrator가 단일 실행기로 조정하며 최종 결과는 `docs/VERIFICATION.md`와 QA 보고서에 기록한다.

D4/D5 문항, 60~250문항 목표 규모, 전문가 검수와 운영 공개는 미완료이다. 추가 템플릿은 만들지 않았으며 기존 자리값 템플릿의 검증된 유한 조합 생성 기능을 재사용한다.

## Orchestrator 최종 통합 보완

신규 설명·조작도 개발 검토 전용 전달 게이트를 추가했다. production은 보존된 M0-01 v1.0.0 문서를 전달하고 확장 단계·조작·묶음 선택을 표시하지 않는다. 클라이언트는 콘텐츠 본문 대신 블록 ID 인덱스를 사용한다. 이 경계는 별도 회귀 검사로 확인한다. 사람이 승인한 최신 콘텐츠를 운영에 승격하는 관리 기능은 아직 구현하지 않았다.
