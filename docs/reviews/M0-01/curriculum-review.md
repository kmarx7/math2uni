# M0-01 교육 설계 및 문항 교차 검토

- 검토 역할: Curriculum Architect (AI agent)
- 검토 대상: `docs/specifications/M0-01/lesson-spec.json`, `problem-blueprint.json`, `src/data/m001-expansion.json`
- 판정: **제한된 개발 검토용 구현 준비 — implementation-ready**
- 문항 상태: 신규 30개 모두 `draft`, 사람 승인 0개, 운영 게시 승인 0개
- 별도 전제: Developer의 독립 수학 계산·스키마·정답 비노출·진도 회귀·브라우저 QA 통과

## 교수학습 구조

기존의 `place`, `compose`, `infer` 기술 ID와 기본 문항/평가/블록 ID를 유지한다. 6개 소단원은 수와 숫자 → 자리와 단위 → 0의 역할 → 분해·묶음 교환 → 비교·변화 → 조건 추론·오류 교정으로 이어진다.

15개 학습 단계는 9개 기존 블록 안의 교육적 단계로 표현할 수 있다. 새로운 블록 확인을 과거 사용자에게 강제하여 기존 단원 완료를 취소하지 않는다. 실제 화면의 6소단원/15단계 지원 여부는 구현 보고서와 브라우저 QA에서 확인해야 한다.

초보 학습자를 위해 자리 이름·숫자·나타내는 값을 분리하고, 기호식보다 묶음 조작과 전후 비교를 먼저 사용한다. 곱셈·뺄셈 기호가 등장하더라도 M0-01에서 선행 단원을 요구하는 장벽으로 쓰지 않고 ‘같은 크기 묶음 몇 개’, ‘묶음이 몇 개 늘고 줄었는가’로 풀어 설명한다.

## 문항 및 원형 검토

신규 초안은 **10개 사고 전략 × 연습 2개 + 평가 1개 = 30개**이다. 원형 ID는 기존 identify/compose/infer 3개를 재사용하고 m001x- 접두사의 신규 7개를 추가한다. 기존 고정 6개/생성 샘플 2개를 신규 초안 수량에 재집계하지 않는다.

| 사고 전략             | 판단 대상                       | 초안 수 | 검토                                 |
| --------------------- | ------------------------------- | ------: | ------------------------------------ |
| identify              | 지정 숫자의 자리 단위와 값      |       3 | 자리 인덱스·자리 단위 일치           |
| compose               | 주어진 단위별 양의 합성         |       3 | 0 자리 보존·합성 결과 일치           |
| infer                 | 숫자 간 관계를 만족하는 수      |       3 | 관계 조건·자리 범위·해 유일성 일치   |
| zero-placeholder      | 지정한 0 삭제의 영향            |       3 | 삭제 위치와 전후 숫자열 일치         |
| representation-match  | 여러 분해식의 동치 여부         |       3 | 매 선택지 값 대조, 동치 선택지 한 개 |
| regroup-equivalence   | 비표준 묶음의 교환              |       3 | 같은 양 보존·남은 단위 개수 일치     |
| compare-lexicographic | 처음 다른 높은 자리로 대소 판단 |       3 | 대소 방향·첫 차이 자리 일치          |
| digit-change          | 한 자리 조작의 전후 변화량      |       3 | 증가/감소 방향과 양 일치             |
| error-diagnosis       | 제시 주장 중 거짓과 교정        |       3 | 선택지별 주장 대조, 거짓 한 개       |
| constrained-extrema   | 카드 제약 아래 극값             |       3 | 각 카드 1회·선행 0 금지·극값 일치    |

숫자만 바꾼 문항은 같은 원형이다. 원형 수는 문제 수나 객관식/숫자 입력 방식으로 부풀리지 않는다. representation-match는 구성하기와 동치 판별하기를 구분한 교육 설계 분류이나, 최종적인 원형 경계의 교육적 타당성은 사람 검수 대상이다.

### 독립 정답 기준 대조

30개의 문제 본문·답·해설을 읽고 별도 기준값과 대조했다. 연구 담당자가 작성한 answerRule을 다시 정답으로 가정하지 않고 자리 계산·합·조건 대입·순서·카드 배치에서 기준값을 정했다. 일치 결과는 **30/30**이다. 이 단순 대조는 개발 담당자의 전수 열거·정합성 테스트와 별도로 수행한 교육 설계 검토이며 자동 테스트 전체 통과를 뜻하지 않는다.

- 식별: 600 / 10 / 9000
- 합성: 3072 / 8405 / 5009
- 조건 추론: 4093 / 6274 / 7082
- 지정 0 삭제: 452 / 608 / 790
- 표현 동치 선택지: b / a / c
- 묶음 교환: 6 / 4 / 30
- 수 비교: 4102 / 5860 / 6307
- 자리 변경의 양: 700 / 70 / 5000
- 오류 선택지: b / a / c
- 카드 극값: 9410 / 2047 / 2036

평가 10개는 연습 20개와 다른 문제 ID/본문이며 확장 평가 전체 응답 후에만 피드백을 제공한다. 기본 3문항 평가와 같은 점수 필드에 섞거나 기본 완료 조건을 변경하지 않는다.

## 교차 검토에서 발견하고 조정한 사항

1. **0 삭제 설명의 방향**: ‘뒤 숫자의 자리가 바뀐다’는 초기 설계 문구는 잘못이다. 3,042 → 342에서 삭제한 0보다 왼쪽 숫자 3의 자릿값이 달라지고, 오른쪽 4는 십·2는 일의 자리를 유지한다. 명세를 정정했고 연구 초안도 같은 규칙을 따른다.
2. **한 자리 변경의 목표**: 초안 초기에는 바뀐 수 자체를 물어 단순 합성과 사고 구조가 가까웠다. 변경된 자리 단위의 전후 차이인 700/70/5000을 묻도록 연구 담당자와 합의해 수정했다. 증가/감소 방향과 양을 구분하며 음수 선행 개념을 요구하지 않는다.
3. **난도 과장 방지**: 네 장의 카드로 최댓값·최솟값을 만드는 현재 초안은 D3로 분류한다. 단순 카드 정렬을 D5라 부르지 않는다. D4/D5는 추가 제약 아래 전이 추론을 갖춘 향후 작성 대상으로 명세에 예약한다. 현재 초안에는 D4/D5가 없다.
4. **오류 문항의 설명**: ‘정답은 [거짓 문장]’이라는 마지막 문구는 초보자에게 혼란을 줄 수 있어 ‘틀린 설명’임을 다시 명시하고 참인 값으로 교정하도록 연구 담당자에게 변경 요청했다. 선택지에서 틀린 주장을 찾는 수학적 판정은 일치한다. 연구 담당자가 최종 문항을 ‘틀린 설명은 …이며 그 자리의 바른 값은 …’으로 수정한 것을 확인했다.

## 검수 한계와 미완료

- 이 검토는 AI 역할 간 독립 비교이지 사람이 승인한 교육 콘텐츠가 아니다. 승인된 내용이 채워진 `approved-content.json`을 생성할 근거가 없으며 (승인 대기/null 산출물은 별도) 문항의 `approved`/`published` 이력을 추가하지 않는다.
- 명세의 실제 화면 구현, 키보드·스크린리더 전달, 저장·새로고침·오답 교정은 Developer/QA의 확인이 필요하다.
- 외부 자료의 원문과 이용 조건은 Research Agent 보고서에 별도 기록한다. 현재 문항은 자체 제작 초안이며 기출·교재 문항을 복제한 자료로 취급하지 않는다. 공식 세부 성취기준의 연결은 미검증 상태를 유지한다.
- 학습 효과, 독립 모의평가 성적 향상, 수능 90점 달성 여부는 검증하지 않았다.
- 새로운 LEVEL별 170개 상세 메타데이터 정렬은 `docs/decisions/007-level-allocation.md`의 충돌 기록을 따르며 이번 M0-01 설계로 해결됐다고 보고하지 않는다.

## 인계

Developer는 본 명세를 기준으로 기존 학습 경로를 보존하면서 개발 검토용 확장 묶음을 구현할 수 있다. 문항 정답·개념 변경이 필요하면 연구/교육 역할에 변경 요청을 남기고, 독립 계산 검사와 데이터 버전을 함께 갱신한다. 사람 게시 승인 전 production 차단을 유지한다.

## 실제 공개 학습 설명·조작 구현 교차 확인

읽기 검토한 파일: `src/data/m001-instruction.json`, `src/data/content.ts`, `src/components/place-value-exploration.tsx`. 프로그램 파일은 수정하지 않았다.

- 공개 JSON의 6개 section은 최종 명세의 소단원 설명·활동·확인 목표와 일치한다. 자리값 원리 유도도 같은 단위 열 개와 윗단위 하나의 동치에 근거한다.
- 0 삭제 설명은 3,042 → 342에서 천의 자리 3만 백의 자리로 내려가고 십 4·일 2는 유지된다는 정확한 관계를 전달한다. 다른 예인 4,070 → 470, 6,008 → 608도 같은 규칙이다. 6,008은 왼쪽 0 하나만 지운다고 명시하여 두 0을 한꺼번에 지우는 해석을 배제한다.
- 새로운 묶음 교환 조작은 `백 묶음×100 + 십 묶음×10`과 `교환 후 백 묶음×100 + 남은 십 묶음×10`이 같다. 초기값 3백·12십은 4백·2십, 모두 420이다. 백 묶음이 10개 이상이 되는 범위도 비표준 묶음 표현으로서 수학적으로 유효하며, 천 묶음으로 다시 교환할 수 있음을 설명한다.
- 새로운 자리 변경 조작은 3,042의 백의 자리 0을 d(0~9)로 바꾸므로 결과는 `3042 + 100d`, 증가한 양은 `100d`이다. 다른 자리의 값은 보존되며 음수·다른 자리 받아올림을 요구하지 않는다.
- 공개 phase 메타데이터는 15단계이며 **14개 available + 심화 1개 planned**이다. D4/D5 심화 단계가 이미 구현되었다고 표현하지 않는다.
- 실제 새 조작은 묶음 교환·0 삭제 비교·한 자리 변경의 **3개**이다. 명세의 조건 카드 후보 비교 조작은 아직 미구현이며 설명/고정 문항만 제공한다. 기존 자리표 조작은 별도로 유지한다.
- 기존 9개 블록 ID가 유지되고 확장 학습이 선택 활동이라는 설명을 확인했다. 실제 완료 조건·저장·숙달 증거 격리의 프로그램 동작은 개발/자동 QA 보고서에서 확인해야 한다.

검토 범위 안에서 수학적 차단 오류는 발견하지 않았다. 이 결과는 소스와 텍스트의 독립 교차 확인이며 브라우저 조작 테스트의 통과나 사람의 게시 승인을 대신하지 않는다.
